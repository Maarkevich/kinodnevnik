# Кинодневник

**Личный дневник фильмов и сериалов.** Русскоязычное PWA: работает офлайн, устанавливается на телефон и десктоп, не требует аккаунта и не имеет сервера — все данные живут только на устройстве.

Форк проекта [Open Movie Tracker](https://github.com/r-shafi/open-movie-tracker) (MIT © 2024 R. Shafi) с переработанными хранилищем, навигацией и интерфейсом.

## Для кого это

Для тех, кто смотрит много и по-разному: фильмы, сериалы, мультсериалы, аниме, дорамы. Приложение не пытается быть соцсетью и не рекомендует «что посмотреть всем». Оно ведёт ваш личный учёт: что посмотрели, когда, как оценили, что отложили — и что из этого следует про ваш вкус.

## Что умеет

- **Запись просмотра в пару касаний** — оценка 0,5–5,0 шагом 0,5 (полузвёзды по тапу), дата, статус, метки, текст.
- **Статусы**: «Смотрю», «Пересматриваю», «Брошено». Недомотренное отличается от просмотренного, а «Завершить» превращает активный просмотр в запись дневника.
- **Пересмотры** — отдельными записями, а не перезаписью первой.
- **Сериалы и аниме** — отметок серий поштучно, прогресс по фактическому числу серий сезона.
- **Дневник** — лента, сгруппированная по месяцам и дням, с фильтрами по типу и сортировками.
- **Подборки** — категории поверх TMDb: мультфильмы, аниме, корейские/китайские/тайские/японские дорамы, турецкие и испанские сериалы. Категории — конфиг, а не разметка: добавить новую можно без правки компонентов.
- **Поиск** — по названию, меткам и собственному тексту; понимает транслит с английской раскладки (набранное `abkmv` находится как «фильм») и не различает ё/е.
- **Свои списки** и избранное.
- **Аналитика** — распределение оценок, темп за 12 месяцев, тепловая карта 365 дней с сериями подряд, расхождение с оценками TMDb, индекс нишевости, возраст фильма на момент просмотра, жанры, страны, языки, режиссёры.
- **Где смотреть** — провайдеры для региона RU (Okko, Кинопоиск, Amediateka, More TV, Premier и др.), если TMDb отдаёт по ним данные.
- **Синхронизация файлом** — см. ниже, это не «импорт/экспорт» в обычном смысле.

## Приватность

- Аккаунта нет. Сервера нет. Телеметрии нет.
- Данные лежат в IndexedDB вашего браузера.
- Единственная внешняя связь — запросы к The Movie Database за метаданными и картинками.
- Ваш ключ TMDb хранится только на устройстве и **не попадает ни в репозиторий, ни в резервную копию**.
- Почта, адрес, имя и сайт из загружаемых файлов не читаются и не сохраняются.

## Синхронизация, а не импорт

Импорт резервной копии работает как слияние:

- **добавляется только то, чего нет** — повторный импорт того же файла не создаёт ни одной лишней записи;
- один и тот же фильм, отмеченный на двух устройствах независимо, **не превращается в дубль**: слияние идёт по семантическому ключу `(тип, id, дата)`, а не по UUID записи;
- **два просмотра одного дня остаются двумя** — это пересмотры, а не дубликат;
- **удалённое не возвращается**: при удалении остаётся надгробие на 90 дней, и импорт с другого устройства его уважает;
- при конфликте **ручная правка важнее импортированной**, иначе побеждает более свежая версия;
- перед записью делается снимок состояния, импорт можно **отменить одной кнопкой**;
- после слияния показывается отчёт: добавлено, обновлено, уже было, отклонено после удаления, конфликты.

## Первый запуск

1. Откройте приложение.
2. Введите ключ API TMDb (**Настройки → Данные TMDb · Ключ API**, получить на [themoviedb.org/settings/api](https://www.themoviedb.org/settings/api), тип **API Key (v3 auth)**).
3. Отметьте первый фильм кнопкой **⊕** внизу.

Без ключа приложение остаётся полезным: дневник, списки, оценки и аналитика работают, недоступен только поиск новых тайтлов.

> Ключ вводится на устройстве и никуда не уходит, кроме `api.themoviedb.org`. Это клиентское приложение без сервера, поэтому ключ виден в сетевых запросах браузера — так устроено любое подобное PWA, а не только это.

## Устройства

Android (Chrome), iOS (Safari, «На экран «Домой»»), десктоп до 1440 px.

**На iPhone это важно не только ради удобства:** в обычной вкладке Safari хранилище живёт неделю и может быть очищено системой, а `navigator.storage.persist()` там не реализован. Установленное на домашний экран приложение этого риска почти не имеет — поэтому при первом запуске показывается подсказка установки.

## Технологии

Angular 21 · Ionic 8 · TypeScript 5.9 · IndexedDB · собственный Service Worker · PWA.

Никакого i18n-слоя: русский — исходный язык приложения, строки написаны по-русски прямо в коде. Локаль `ru` задана через `LOCALE_ID`, поэтому даты, числа и плюралы берёт движок.

Офлайн — основное состояние, а не запасной режим: дневник, списки, оценки и аналитика не требуют сети, постеры берутся из кэша, а экран фильма строится из сохранённого снимка и не бывает пустым при 404 или отсутствии связи.

**Обновления.** Все артефакты сборки содержат хэш в имени файла, поэтому устареть не могут. Service Worker проверяет новую версию при старте, при возврате в приложение и каждые 30 минут; найденное обновление предлагается кнопкой, а не применяется молча — посреди незаполненной формы перезагрузка была бы вредна. GitHub Pages отдаёт всё с `Cache-Control: max-age=600` и переопределить это нельзя, поэтому за свежесть отвечает SW, а не HTTP-заголовки.

## Дизайн

Тёмная тема, акцент `#49effb`, шрифт [Nunito](https://fonts.google.com/specimen/Nunito) (полная кириллица, раздаётся вместе с приложением — при первом запуске без сети он тоже Nunito), скруглённые углы, «стеклянные» оверлеи.

Стекло — только на слоях (листы, модалки, поповеры, алерты, тулбар и таббар), а не на каждой карточке: 18 размытых слоёв в скроллящейся ленте это джарки на среднем Android. Под светлыми постерами стекло обязано иметь затемняющую подложку, иначе текст падает до 2.5:1. Уважаются системные `prefers-reduced-transparency` и `prefers-reduced-motion`, масштабирование пальцем не запрещено.

## Разработка

```bash
npm install
npm start            # ng serve, http://localhost:8100
npm run prebuild     # генерация src/environments/version.ts и public/version.json
npm run build        # прод-сборка + sw.js + sw-manifest.json + 404.html
npm test             # unit-тесты (Karma, нужен Chrome)
npm run check:sync   # 17 проверок правил слияния, без браузера
npm run verify       # гейты сборки: buildId, прекеш, кириллица, отсутствие ключей
npm run e2e          # Playwright
```

Коммиты — [Conventional Commits](https://www.conventionalcommits.org/). Ветка `main` защищена, всё через PR. Деплой на GitHub Pages — по пушу в `main`.

Полное описание продукта, архитектуры и правил — в **[docs/SPEC.txt](docs/SPEC.txt)**. Документ является контрактом: если поведение расходится со спецификацией, это баг.
